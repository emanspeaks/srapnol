# C ABI round trip

**Purpose.** Confirm a consumer that sees only the built shared library and its generated header can solve the toy problem through the C interface with the same result as the native call, and that invalid input is rejected with error codes.

**Grouping.** Requirements verification; interface.

**Software version.** The version under test is recorded in the Software Test Report; this procedure applies from 0.1.0.

**Prerequisites.** Repository checked out at the version under test; toolchain and `rstd` per STP section 4.

**Steps.**

1. Run `zig build test` (toolchain per STP section 4).
2. Build the shared library with `zig build shim`; compile and run `src/test/cabi/main.c` against it; observe its assertions.

**Inputs.** The toy problem expressed through the C API; deliberately invalid handles and lengths.

**Expected results.** Same `x`, objective, and exit code as the native solve; invalid inputs return the documented negative codes without crashing; the library links without libc symbols beyond the loader's.

**Pass/fail criteria.** Pass when every listed test reports success. A test that reports skipped counts as a pass only while every requirement it verifies has `status: pending` in SRS; otherwise the procedure fails.

**Rerun.** Repeatable without cleanup; the procedure is deterministic and has no external state.
