# snOptA toy problem

**Purpose.** Confirm the three layouts of the manual's toy problem (objective in `G`, objective in `A`, feasible-point only) validate, agree on `F`, pass the Jacobian check, and solve to the documented optimum; feasible-point mode exits `feasible_point`.

**Grouping.** Requirements verification.

**Software version.** The version under test is recorded in the Software Test Report; this procedure applies from 0.1.0.

**Prerequisites.** Repository checked out at the version under test; toolchain and `rstd` per STP section 4.

**Steps.**

1. Run `zig build test` (toolchain per STP section 4).
2. Observe the `toy:` tests.

**Inputs.** `x0 = (1, 1)`; the three layouts; default options.

**Expected results.** `F` at the optimum is `(-1, 4, 5)`; layouts agree to `1e-15`; Jacobian within `1e-8`; solves reach `(0, -1)` within `1e-6` with `Exit.optimal`; feasible-point mode exits `feasible_point` with objective 0.

**Pass/fail criteria.** Pass when every listed test reports success. A test that reports skipped counts as a pass only while every requirement it verifies has `status: pending` in SRS; otherwise the procedure fails.

**Rerun.** Repeatable without cleanup; the procedure is deterministic and has no external state.

**Zig test names.**

- `toy: F at the documented optimum, in every layout`
- `toy: objective-in-G and objective-in-A agree on the full F`
- `toy: analytic G matches central differences`
- `toy: every layout validates`
- `toy: solve with the objective row in G`
- `toy: solve with the objective row in A`
- `toy: feasible point only`
