# Truss acceptance solve

**Purpose.** The primary acceptance case: solve the truss from the generic start with default options and reach the benchmark optimum with the correct active set and multiplier.

**Grouping.** Requirements verification; acceptance.

**Software version.** The version under test is recorded in the Software Test Report; this procedure applies from 0.1.0.

**Prerequisites.** Repository checked out at the version under test; toolchain and `rstd` per STP section 4.

**Steps.**

1. Run `zig build test` (toolchain per STP section 4).
2. Observe `truss: solve from the generic start reaches the benchmark optimum`.

**Inputs.** `x0 = (5e-4, 5e-4)`, default `Options`, cold start.

**Expected results.** `Exit.optimal`; `x` within `1e-5` relative; objective within `1e-6`; `sigma3` at its bound within `1e-6` relative; `f_state[3] == nonbasic_lower`; `f_mul[3]` within `1e-3` of `lambda*`; every row within its bounds; at least one major iteration and one evaluation.

**Pass/fail criteria.** Pass when every listed test reports success. A test that reports skipped counts as a pass only while every requirement it verifies has `status: pending` in SRS; otherwise the procedure fails.

**Rerun.** Repeatable without cleanup; the procedure is deterministic and has no external state.

**Zig test names.**

- `truss: solve from the generic start reaches the benchmark optimum`
