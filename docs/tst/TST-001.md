# Problem validation

**Purpose.** Confirm every rejection condition of the input validation requirement is detected before any callback, with a distinct error, and that a well-formed problem is accepted.

**Grouping.** Requirements verification; regression.

**Software version.** The version under test is recorded in the Software Test Report; this procedure applies from 0.1.0.

**Prerequisites.** Repository checked out at the version under test; toolchain and `rstd` per STP section 4.

**Steps.**

1. Run `zig build test` (toolchain per STP section 4).
2. Observe the `validate:` tests and `addLinear adds only the declared triplets`.

**Inputs.** A 2x2 skeleton problem with a no-op callback, mutated one defect at a time: inverted bounds, a slot in both `A` and `G`, duplicate `G` entries, out-of-range indices, `obj_row >= nf`, mismatched lengths.

**Expected results.** Each defect yields the matching `Problem.ValidateError`; the well-formed problem validates; `addLinear` adds exactly the declared triplets.

**Pass/fail criteria.** Pass when every listed test reports success. A test that reports skipped counts as a pass only while every requirement it verifies has `status: pending` in SRS; otherwise the procedure fails.

**Rerun.** Repeatable without cleanup; the procedure is deterministic and has no external state.

**Zig test names.**

- `validate: accepts a minimal well-formed problem`
- `validate: rejects inverted bounds`
- `validate: rejects a slot declared in both A and G`
- `validate: rejects duplicate G entries`
- `validate: rejects out-of-range indices`
- `validate: rejects obj_row past nf and mismatched lengths`
- `addLinear adds only the declared triplets`
