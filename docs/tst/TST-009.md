# Preprocessing edge cases

**Purpose.** Confirm unsorted sparse input, fixed variables, and constant rows are handled by the problem transformation.

**Grouping.** Requirements verification.

**Software version.** The version under test is recorded in the Software Test Report; this procedure applies from 0.1.0.

**Prerequisites.** Repository checked out at the version under test; toolchain and `rstd` per STP section 4.

**Steps.**

1. Run `zig build test` (toolchain per STP section 4).
2. Observe the `preprocess:` tests.

**Inputs.** The toy problem with its `A` and `G` entries shuffled; the truss with `x2` fixed at its optimum; a problem with an all-zero row bounded to contain zero and one bounded to exclude it.

**Expected results.** Shuffled input reaches the same solution as sorted input; the fixed-variable solve keeps `x2` fixed and optimizes `x1`; the feasible constant row is accepted and the infeasible one exits `infeasible_linear_constraints` before any callback.

**Pass/fail criteria.** Pass when every listed test reports success. A test that reports skipped counts as a pass only while every requirement it verifies has `status: pending` in SRS; otherwise the procedure fails.

**Rerun.** Repeatable without cleanup; the procedure is deterministic and has no external state.
