# Truss stress invariant

**Purpose.** Validate the three-bar truss test data: `sigma1 + sigma3 == sigma2` holds identically, so the callback can be trusted as a reference.

**Grouping.** Test-data validation.

**Software version.** The version under test is recorded in the Software Test Report; this procedure applies from 0.1.0.

**Prerequisites.** Repository checked out at the version under test; toolchain and `rstd` per STP section 4.

**Steps.**

1. Run `zig build test` (toolchain per STP section 4).
2. Observe `truss: sigma1 + sigma3 == sigma2 at every design point` and `truss: problem definition validates`.

**Inputs.** A 5x5 logarithmic grid over the area bounds `[1e-6, 1e-2]`.

**Expected results.** The identity holds to `1e-10` relative at every grid point; the problem validates with 6 `G` and 2 `A` entries.

**Pass/fail criteria.** Pass when every listed test reports success. A test that reports skipped counts as a pass only while every requirement it verifies has `status: pending` in SRS; otherwise the procedure fails.

**Rerun.** Repeatable without cleanup; the procedure is deterministic and has no external state.

**Zig test names.**

- `truss: sigma1 + sigma3 == sigma2 at every design point`
- `truss: problem definition validates`
