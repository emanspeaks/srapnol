# Hessian and superbasics options

**Purpose.** Confirm the full-memory Hessian reaches the same optima as limited memory, that curvature safeguards keep the update positive definite on a nonconvex problem, and that the superbasics limit is enforced.

**Grouping.** Requirements verification.

**Software version.** The version under test is recorded in the Software Test Report; this procedure applies from 0.1.0.

**Prerequisites.** Repository checked out at the version under test; toolchain and `rstd` per STP section 4.

**Steps.**

1. Run `zig build test` (toolchain per STP section 4).
2. Observe the `hessian:` and `superbasics:` tests.

**Inputs.** HS47 and HS15 with `hessian = .full_memory`; HS15 (Rosenbrock, indefinite away from the optimum) with the update-skip counter exposed; HS47 with `superbasics_limit = 1`.

**Expected results.** Full-memory solves match the limited-memory optima within the same tolerances; at least one modified or skipped update occurs on HS15 and every accepted update leaves `R` positive definite; the limited run exits `superbasics_limit`.

**Pass/fail criteria.** Pass when every listed test reports success. A test that reports skipped counts as a pass only while every requirement it verifies has `status: pending` in SRS; otherwise the procedure fails.

**Rerun.** Repeatable without cleanup; the procedure is deterministic and has no external state.
