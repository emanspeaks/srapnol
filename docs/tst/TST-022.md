# Callback statuses and errors

**Purpose.** Confirm the status sequence and the handling of `Undefined`, `Abort`, and non-finite values.

**Grouping.** Requirements verification.

**Software version.** The version under test is recorded in the Software Test Report; this procedure applies from 0.1.0.

**Prerequisites.** Repository checked out at the version under test; toolchain and `rstd` per STP section 4.

**Steps.**

1. Run `zig build test` (toolchain per STP section 4).
2. Observe the `callback:` tests.

**Inputs.** The toy problem with a callback that records statuses; variants returning `error.Abort` on the third call, `error.Undefined` at `x0`, `error.Undefined` in a region the line search must back out of, and NaN in `f`.

**Expected results.** Exactly one `.first` and one `.last`; `Abort` exits `user_terminated`; `Undefined` at `x0` exits `undefined_at_initial_point`; backing out succeeds or exits `cannot_proceed_into_undefined_region`; NaN behaves as `Undefined`; `f` is never requested outside the bounds or linear rows.

**Pass/fail criteria.** Pass when every listed test reports success. A test that reports skipped counts as a pass only while every requirement it verifies has `status: pending` in SRS; otherwise the procedure fails.

**Rerun.** Repeatable without cleanup; the procedure is deterministic and has no external state.
