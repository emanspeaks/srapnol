# Basis factorization

The basis `B` (`m x m`, `m = nf - 1`) is first implemented as a dense LU with partial
pivoting: refactor after a fixed number of updates, row-replacement updates in between,
SIMD row axpy in elimination and updates. The interface (`factor`, `solve`,
`solveTranspose`, `replaceColumn`, `conditionEstimate`) is the one a sparse LUSOL-style
factorization (Markowitz ordering, threshold partial pivoting, Bartels-Golub or
Forrest-Tomlin updates) implements later without touching the QP solver. A dense `B`
caps practical size at a few thousand rows: `m^2` doubles and `O(m^3)` per
refactorization. Singular or ill-conditioned bases are repaired by swapping in slack
columns; if repair fails the solve exits 42 or 44.
