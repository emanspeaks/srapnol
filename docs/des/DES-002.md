# States and modes

The solver has one operating mode with three start variants (`cold`, `basis`, `warm`),
a feasible-point variant selected by `obj_row == null`, and an elastic sub-mode entered
when a QP's linearized constraints are infeasible and left when infeasibility is
driven to zero. No other state persists across calls: `Solver` holds the workspace,
`State` holds the iterate, and both are owned by the caller.
