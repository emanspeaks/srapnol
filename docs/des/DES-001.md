# Behavioral contract: the snOptA split

The library adopts the snOptA problem form and evaluation contract unchanged: the user
declares the constant sparse \(A\) and the sparsity pattern of \(G\), the callback
returns only \(f(x)\) and the \(G\) values in pattern order, and the solver assembles
\(F = f + Ax\) and \(J = G + A\). Linear rows (no \(G\) entries) and linear variables
(no \(G\) column entries) are treated exactly and never enter the merit function or the
Hessian. This is why the objective's linear part belongs in \(A\): it keeps the Hessian
small and the linear part exact.
